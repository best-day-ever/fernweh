# 1.2.31 — bounded Host bitrate pacing

The Linux Host replaces its blanket1Gb/s sender budget with an enforced
bitrate-derived Quinn pacing ceiling. Encoder peak headroom is bounded to
1.5times the selected video target, with40% repair/header allowance and1Mb/s
for audio/control. A50Mb/s video selection permits71–106Mb/s of paced QUIC
traffic, with at most26,500bytes of saved two-millisecond burst credit at the
upper budget. Idle time cannot bank a larger burst.

This preserves controlled codec/keyframe headroom. Encoder settings, profiles,
FEC, media queue sizes and authentication remain unchanged. Existing compatible
Clients require no update. The direct CUDA/NVENC lifecycle repair remains.
This bounds sender bursts; it does not claim to identify the cause of a
particular network loss or freeze. Adaptive congestion backoff is unchanged.

Regression coverage includes encrypted packet/GSO rate envelopes, live bitrate
reductions, authenticated endpoint isolation and idle recovery. The native
streaming runner requires three loss matrices each for CBR and VBR peaks,
retaining its existing payload, recovery and latency gates. Both Host build
paths require the vendored pacing tests and the bitrate-paced binary marker.
See [the pacing contract](../development/bitrate-pacing.md) for the limits and
qualification requirements.
