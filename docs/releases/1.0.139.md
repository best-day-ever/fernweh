# BDE fernweh 1.0.139 — client updates from the broker

The Mac app now uses **BDE fernweh** in its window, onboarding, macOS metadata, Touch ID prompt, and user-facing messages. Its internal bundle identifier, settings namespace, and broker protocol names remain stable so existing sign-ins and settings survive the upgrade.

On launch and every six hours, the app checks the pinned broker for a newer Apple Silicon release. When one is available, the launcher shows **Update to <version>**; Settings also offers **Check for updates**. The update downloads over the existing TLS 1.3 broker pin, verifies its SHA-256 and size, then verifies the notarized DMG and that its app has the same Apple signing team and bundle ID as the installed app. After the client exits, it replaces the app and reopens it. A protected Applications folder triggers the normal macOS administrator prompt. A failed verification leaves the installed app in place.

The broker serves `GET /v1/client-updates/macos-arm64` and its versioned `.dmg` route without a login, allowing update checks before first sign-in. Operators publish the immutable, notarized DMG and verify its checksum before atomically exposing `current.json`. The broker reads the feed on each request, so later releases require no broker restart.

Existing 1.0.138 and older clients need one manual install of 1.0.139 because they do not contain the update control. Subsequent versions can be installed from inside BDE fernweh.
