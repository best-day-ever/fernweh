# 1.2.42 — Windows fullscreen recovery and requested diagnostics

Restore deterministic initialization of the retained SDL session runtime after
the Qt integration. Its fullscreen flag and window-event flush counter were
left uninitialized, which could prevent fullscreen or discard the events needed
to recreate a deleted decoder. Session teardown/thread state also has explicit
defaults. Fullscreen changes explicitly request decoder recreation whenever
they remove it, including same-size or refused window transitions.

Broker-enabled Clients can answer an administrator's expiring diagnostic
request with a bounded, redacted application-log tail and the current or last
session report while the app is open, including during a stream. Windows SDL
messages now reach the persistent application logger. The existing diagnostics
opt-out also stops requests and clears the buffer. No remote command, arbitrary
file, screenshot, audio or clipboard collection is added.

The broker receives bundles only for an active, account-scoped operator request,
using the existing device-bound authentication. Older Clients keep their
summary-upload contract; older brokers answer the new polling path as absent.
Install the updated broker before enabling collection from updated Clients.
See [operation](../fernweh/diagnostics.md) and [wire/storage contract](../../protocol/client-support-diagnostics.md).

This source version reserves a new package identity. Native build, package and
installed fullscreen/streaming acceptance must pass before promoting a binary.
The independent Mac and Linux deployment selections need no automatic update.
