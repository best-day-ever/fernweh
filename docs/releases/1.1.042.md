# BDE Fernweh 1.1.042

The Mac Client can send files and folders using the streaming toolbar's **Files…**
button, alongside Finder copy/paste. This Mac-only update uses the existing
Linux Host file protocol and per-user file-transfer grant; no new Host is required.

- Open the destination folder on the remote desktop, reveal the toolbar at the
  top edge, click **Files…**, and select local files or folders. When **Files sent**
  appears, press **Ctrl+V** in the remote folder.
- For clipboard transfer, copy files in Finder with **⌘C**, focus the remote file
  manager and press **Ctrl+V**. Ctrl+V also works in immersive keyboard mode.
  Files already staged by the same copy can be pasted again without retransmission.
- To receive files, copy them in the remote file manager. Wait for **Files received**,
  then paste in Finder with **⌘V**. A newer local copy or lost stream focus is
  preserved instead of being overwritten by a completed remote download.
- The toolbar reports sending, receiving, completion and failure. The picker
  transfers without changing the local clipboard and leaves the final remote
  paste to the user.
- Opposite-direction offers yield and retry the saved local selection. Corrupt
  data, malformed records and silent peers cannot leave the worker waiting forever.
  Remote file URLs are not reflected back to the Host as a new local copy, and
  focus changes cancel deferred keyboard injection.

Regular files and folders are supported. Links, special files, resource forks
and extended attributes are outside the existing protocol. Text clipboard and
file-transfer permissions remain separate and enforced by the Host.

Native Mac tests exercise the production AppKit pasteboard adapter and file I/O
against an in-memory PCF2 peer. They verify byte reconstruction, hashes, policies,
clipboard ownership, crossed offers, malformed-input recovery and deferred paste.
Those tests do not substitute for a paired Finder-to-Linux desktop session.
