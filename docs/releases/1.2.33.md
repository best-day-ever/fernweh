# 1.2.33 — Windows video recovery

The native video receiver now retries keyframe recovery at most once per
second while complete delta frames continue arriving. Previously, a lost or
unusable recovery response could leave the decoder waiting forever, even
though the transport was still delivering frames. Recovery timing belongs to
the receiver; decoder refresh crosses threads through an atomic handoff.

Windows D3D11 presentation uses nonblocking swap-chain submission. Queue
backpressure and window occlusion defer presentation rather than requesting a
device reset. Device failures request one reset after the event is queued.
The shared graphics context remains serialized.

The frame pacer releases discarded hardware frames outside its queue lock,
avoiding device callbacks under that lock. Diagnostics exclude initialization
sentinels and reset stale statistics between receiver generations. Local logs
add bounded pipeline stage snapshots; the existing private structured-report
format and opt-out remain unchanged.

Diagnostics worker completion now reaches the owner thread before notifying
observers, so an immediate upload cannot be skipped because the worker still
appears busy. A Windows-discovered regression protects this ordering.

The selected codec, chroma, depth, bitrate and sender pacing policy remain in
effect. This Windows ALPHA client update repairs reproduced recovery defects;
affected-hardware reports are still needed to establish field stability. It
does not promise cancellation of arbitrary graphics-driver hangs.

Native recovery tests exercise H.264 and HEVC in direct and pull modes, lost
keyframe responses, retry timing, idle cadence, decoder refresh, queue overflow
and concurrent refresh. Pacer ownership, diagnostics and Windows presentation
tests run alongside the existing Windows client and MSI service-access gates.

Only the Windows client package is published for this release. Other packages
and installed Host/broker binaries retain their existing versions.
