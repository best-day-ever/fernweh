# 1.2.36 — Startup and disconnect diagnostics

Broker-prepared Client sessions include a bounded lifecycle snapshot in beta
diagnostics: last startup phase, first initiating termination reason, numeric
error, native-window creation, decoder readiness, video receipt and renderer
progress. This distinguishes a stream closed immediately after negotiation
from a demonstrated presentation path, even before the first periodic sample.

SDL and Qt sessions record window/decoder/display failures, application and
thread exit, window close, disconnect controls, transport/reconnect endings and
negotiated video-format changes. Cleanup preserves the initiating cause; early
exits and destruction before execution also finalize their report.

The broker accepts the optional strictly typed snapshot and retains acceptance
of older reports. Update the broker before distributing this Client; older
strict parsers reject the new field. Existing report opt-out, device-bound
upload, idle timing, retention and size limits remain. Ordinary text logs stay
local. Older reports cannot recover missing termination details.

This release improves diagnosis; it does not claim to repair the initiating
startup or GPU failure. Windows packaging and native qualification must pass
before publication. Existing Linux Host and Mac Client feeds need no change.
