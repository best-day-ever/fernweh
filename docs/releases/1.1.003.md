# 1.1.003 — Fernweh input reliability and immersive keyboard

The Mac Client preserves a first click in the video region while initial
capture activates. It reports bounded warnings if a click cannot be positioned
or queued, without recording pointer coordinates or keys.

Mac Settings now offer immersive keyboard mode for the next connection. While
the stream has focus, ordinary keyboard shortcuts, including Option-Tab as
remote Alt-Tab, are forwarded to the Host. Ctrl+Alt+Shift+Z leaves immersive
mode for the current session. Protected macOS shortcuts and local gestures
remain local. Accessibility permission is required for system shortcuts.

The Linux Host refuses to serve a session if the virtual keyboard or mouse
could not be created. Its supervisor retries the failed worker instead of
leaving a video-only session. Other Host platforms retain their startup
behavior.

The Mac development build, native keyboard capture tests, root CI and a
focused Rocky 9.7 fake-device readiness test passed. The intermittent
first-connection click failure was not reproduced, so its cause remains
unconfirmed. Release qualification requires a native Rocky Host RPM build and
a signed Mac Client with physical first-click and shortcut acceptance.
