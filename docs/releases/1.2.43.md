# 1.2.43 — Reject stale capture buffers during Linux display changes

The Linux Host checks every successful NvFBC grab against the current capture
dimensions and available BGRA bytes before duplicate filtering or CUDA copies.
A resized, truncated or incompatible frame requests complete capture
reinitialization instead of being interpreted with the old row stride. Packed
arrangements validate their whole-screen source independently of the packed
destination size.

Native component tests and an actual-production snapshot fixture cover smaller,
larger, equal-byte/different-stride, duplicate and truncated frames. Standalone
NVIDIA capture recovers across 1920×1080, 3024×1898 and 1512×949 logical viewports,
with all five readbacks matching independently captured source RGB pixels.

This reserves a Linux Host package identity. Installed streaming and pointer
acceptance remain package qualification gates. Clients 1.2.42 remain compatible;
this change requires no new Client, broker, driver or desktop setting.
