# 1.2.34 — Windows updater before elevation

The Windows updater now changes only the download directory/file DACL through
the .NET filesystem API. Windows PowerShell's Set-Acl attempts to copy owner,
group and auditing too. Its normal-user fallback can fail before the UAC prompt
with "Some or all identity references could not be translated" when a group SID
has no account-name mapping. An elevated-only test does not exercise that path.

Owner, group, auditing and inheritance protection remain unchanged. Only SYSTEM
and the built-in Administrators group receive read/execute on the exact Qt
download directory and MSI. No new write or general-user access is granted.

The package gate now requires a real limited-token Windows PowerShell5.1 test
with both Qt's ordinary owner-only directory and an unmapped group SID. It
reproduces the previous failure and exercises the complete production helper
through the elevation boundary, alongside real Windows Installer extraction.

An affected installation still launches its embedded old helper, so publishing
a new MSI cannot repair that earlier step. Install this MSI directly once,
then use the repaired in-app updater for later releases. Account data and
preferences are retained. The video recovery fixes from1.2.33 are included;
codec/profile, quality, Host and broker binaries are unchanged.
