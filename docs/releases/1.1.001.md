# 1.1.001 — BDE coordinated release

Update Host and Client together. RaptorQ 2.0.1 changes recovery data on the
wire; native transport negotiation rejects older incompatible peers rather
than attempting to decode mixed-version data. The new macOS microphone setup
also requires a matching Client. Do not pair this line with the previous
published release.

## Client

- Microphone forwarding to macOS Hosts, automatic/manual controls and toolbar mute.
- Automatic first-use Host identity storage and explicit replacement confirmation.
- Safer malformed-data handling, connection cancellation and rendering shutdown.
- More reliable audio/video startup and queue handling.

## Host

- RaptorQ 2.0.1 recovery and removal of the application datagram pacer.
- macOS virtual microphone input with automatic selection/restoration.
- More tolerant, bounded certificate preparation during first login after reboot.
- Bounded Linux PAM authentication and incoming-data validation.

This version number starts the 1.1.xxx line at the operator's request. Client
and Host packages are built from the merged 1.1.001 source; earlier 1.0.x
candidates remain separate.

## BDE integration

The BDE branch keeps its broker leaf pin, GSSAPI admission, display arrangement
and macOS 13 Client floor. It assigns virtual primary connector to `0x10000000`
and macOS text clipboard to `0x800000`, avoiding existing BDE NVENC 4:2:0 and
desktop sign-out allocations.

The Mac Client and macOS Host synthetic suites, Rust transport, root policy
tests and signed/notarized package gates passed. The native Mac transport
passed three 150 Mbps loss matrix trials. On a Rocky 9.7 x86_64 buildbox,
the Linux Host passed its PAM/HTTPS tests, 267 focused Host tests (one
separately covered test skipped) and three native 150 Mbps loss matrix trials;
the RPM package gate passed. A matched candidate Client and Host completed
brokered GSSAPI login and rendered the canary desktop, then disconnected
cleanly. The macOS Host's privileged cross-UID HTTPS handoff fixture and live
Mac Host hardware acceptance remain unverified; its package is staged for a
Mac Host target. Release artifacts and BDE pins are recorded in bde-linux.

## Windows client candidate

The Windows x64 Client is built from the merged 1.1.001 source with the same
native transport. Its executable carries the BDE fernweh icon, Best Day Ever
publisher metadata, and version 1.1.001. A WiX 4 MSI installs the Qt and media
runtime, creates a Start menu shortcut, and supports clean uninstall and
reinstall. Windows Installer records the numeric product version as 1.1.1.

A human verified password/TOTP sign-in, desktop streaming and interactive
input on a Windows test workstation. The MSI payload, installed executable
hash, install, uninstall and reinstall were checked there. Audio, Wacom,
colour and multiple displays remain unverified on Windows. The MSI is an
**unsigned internal candidate** on the BDE transfer share; no Windows update
feed is published. Authenticode signing, the remaining hardware checks, and
Windows device-bound sessions are required before a general Windows release.
Windows Hello is deferred.
