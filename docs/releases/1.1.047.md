# 1.1.047 — Display layout and recovery corrections

The client moves its remaining window to the selected primary display when
applying a layout that reduces two screens to one. Older-workstation Match
Client layouts retain the selected remote primary. Linux captures and refreshes
stable monitor identities on the GUI thread, preserving saved screen selections;
its screen setup dialog remains interactive during streaming and session cleanup.

The Linux host retains each arrangement's original display snapshot and owner
until exact restoration succeeds. Refused re-acquisitions preserve the existing lease, failed
handoff rollback remains retryable, and inventory capture/publication retries
before a new graphical session's media worker starts.

The supervisor service retains its private runtime recovery records across
stops and restarts. Managed workstations receive this setting as a service
override for existing packages; future packages include the same default.
The runtime directory stays root-only and disappears at reboot.

Boot layout positioning uses native physical display dimensions separately from
the remote 60 Hz carrier. Existing inventory caches select their known mode
explicitly, avoiding overlapping screens. Running virtual heads remain reserved
across physical connector changes only when the overlay assignment and live
PLANK EDIDs still verify.

Regression coverage includes display transaction failures, recovery deadlines,
inventory retries, native and legacy boot geometry, saved monitor identities,
primary placement, and Qt setup-dialog dispatch and cleanup ownership.
