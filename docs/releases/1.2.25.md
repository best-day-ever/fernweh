# Fernweh 1.2.25 — Recover the greeter after desktop sign-out

GDM can leave its new login screen waiting for its virtual terminal while the
seat remains on the previous desktop's terminal. Old user records marked closing
then prevent destructive login-manager recovery. The Host could remain running
with no usable graphical session, leaving subsequent clients unable to connect.

The Linux supervisor now activates the unique existing GDM greeter when no
session is active. It protects live user desktops, rejects ambiguous or failed
session queries and requires a real GDM-owned VT with no display operation in
progress. Inactive closing records permit activation, while continuing to block
GDM restarts. The same safe candidate is checked immediately before the bounded
logind command. A short observation delay and per-stall retry budget avoid loops
without limiting successive normal sign-outs.

Seven focused lifecycle/authorization tests pass on native Linux and macOS;
the supervisor compiles as C++23 on Linux. The recorded fault recovered when its
existing greeter was activated: Xorg and GNOME returned and the supervisor
replaced the stale media worker. Full package and installed automatic-recovery
acceptance remain required before promoting the deployment pin.

Client and broker protocols and release feeds are unchanged. This is a Linux
Host lifecycle correction, not a generic periodic service restart.
