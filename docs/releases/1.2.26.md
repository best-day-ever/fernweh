# Fernweh1.2.26 — Explain locked desktops before joining

The Client now offers Join only when the Host explicitly reports that its current
desktop is available for collaboration. A locked desktop explains that its owner
must reconnect and unlock before another person joins. The separate sign-out
path retains its unsaved-work warning and explicit confirmation.

If the desktop locks or disappears between the offer and the sharing request,
the Client reports that sharing is unavailable instead of presenting a generic
authentication rejection. It never unlocks another account's desktop or replays a
one-use broker credential to bypass the refusal. Host and broker authorization
are unchanged.

Validation: SDK27/macOS15-minimum full Client build;38 Qt invocations/766 cases
pass, including strict available/locked/missing/malformed hint regression cases.
A native candidate against an installed Host reproduced the locked-desktop flow,
showed the explanation without Join, and Cancel retained the owner's desktop.
Signed Mac package qualification and feed deployment are recorded separately.
Linux Host deployment remains on the independently qualified1.2.25 package.
