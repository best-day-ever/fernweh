# BDE Fernweh 1.2.23 — Windows update service access

The Windows updater now grants SYSTEM and the built-in Administrators group
read/execute access to its temporary download directory and MSI. Qt deliberately
creates an owner-only directory: the user's hash and package checks succeeded,
but the separate Windows Installer service could not read the downloaded MSI
and returned code110. Other users receive no additional access, and the helper
does not grant write access.

The helper preserves a verbose installer log under the current user's local
application data in `BDE fernweh/updater`. Failed installations show the log
path. Existing account data and application preferences remain in place.

The MSI packaging gate now creates a real Qt temporary directory, proves the
original access-denied/code110 failure, then runs the production helper against
the Windows Installer service. Administrative extraction verifies the packaged
files without changing the builder's installed application. Argument, integrity
and package-identity regressions remain required.

An already-installed broken updater still runs its embedded old helper; a new
MSI cannot repair code that fails before Windows Installer can open the package.
Those installations require one successful installation of this release, either
through managed deployment or by running the studio-published MSI locally.
Subsequent in-app updates use the repaired helper.

This release publishes a Windows Client only. Other platform packages and the
Host/broker deployment remain on their existing versions.
