# Fernweh 1.2.24 — Linux Host display startup

The Linux supervisor waits for a connected physical output or a reserved virtual
head before publishing its startup inventory and starting a capture worker.
An empty observation is retried in the same graphical session. Previously the
empty inventory could remain cached after a monitor appeared, leaving clients
with a temporary-empty-topology response until a manual Host restart.

Free connector candidates are not ready virtual heads. A previously ready
session is not polled or restarted by this change; active desktop ownership,
display leases, hybrid preparation and capture profiles keep their existing
policies. Client and broker protocol contracts are unchanged.

Fourteen native Linux lifecycle/publication tests cover the late physical-output
case, reserved-head admission, old-session cache rejection and existing snapshot
recovery behavior. The supervisor translation unit compiles as C++23, and the
117 root repository CI tests pass. Changed-history privacy checks pass.

This records the source fix. Rocky9.7 package validation and delayed-display
hardware/session qualification are still required before deployment. Existing
Client feeds and deployed Host pins are not updated by this source commit.
